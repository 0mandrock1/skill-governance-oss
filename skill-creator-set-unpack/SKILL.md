# skill-creator-set-unpack

Зворотний бік `skill-creator-set`. Артефакт → жива колекція.

Inherits from: `skill-creator-set`
Overrides: напрямок — читає `MANIFEST.json`, а не пише його
Reuses verbatim: формат `skillset/1`, розкладку `skills/` всередині архіву,
семантику `install_order`

**Крок 0:** read `skill-creator-set` — його `SKILL.md` за шляхом
скіл `skill-creator-set` (його `SKILL.md`). Далі
скіл `skill-creator-framework` (його `SKILL.md`).

---

## Де це запускати

Скрипту потрібен **записуваний корінь скілів**. У claude.ai-чаті його нема:
`/mnt/skills/` read-only, а контейнер помирає разом із сесією. Тому запуск —
там, де колекція жива:

| Середовище | Корінь | Як |
|---|---|---|
| Cowork | `~/.claude/skills` | напряму, дефолтний `--into` |
| Домашній Windows | WSL-шлях до колекції | `node-b-desktop` |
| VPS | `{collection-root}` | `node-a-ssh` або `cc-remote-agent-vps` |

Скачаний з claude.ai файл лежить у Downloads — шлях до нього дає Mark, не вгадувати.

**Виняток — claude.ai-чат.** Записуваного кореня тут нема взагалі, тож установка
неможлива. Але розібрати бандл назад на окремі `.skill` можна, і саме вони тоді
є результатом — Mark качає їх поштучно:

```
python scripts/unpack_bundle.py <bundle>.skillset --emit-skills <dir>
```

Members копіюються байт-у-байт, тому їхні sha256 і далі збігаються з маніфестом:
перевипуску не відбувається, і ці файли рівноцінні тим, що клав `skill-creator-pack`.
Далі `present_files` на них. Це **не** установка — сказати це Марку прямо,
інакше легко подумати, що скіли вже в колекції.

## Процедура

1. **Dry-run завжди перший.**
   ```
   python scripts/unpack_bundle.py <bundle>.skillset --into <root> --dry-run
   ```
   Показує причину бандла, дату збірки і що саме поїде. Нічого не пише.
2. **Прочитати `reason` вголос Марку.** Якщо причина не збігається з тим, чого
   він чекає — це не той бандл, зупинитись.
3. **Встановити.** Без колізій — просто прогін без `--dry-run`. З колізіями
   скрипт відмовляє і перелічує їх; тоді `--force`, який **перейменовує** наявну
   теку в `<name>.bak-<timestamp>`, а не видаляє.
4. **Прогнати лінти** по корені (скрипт друкує обидві команди наприкінці):
   `lint_dependencies.py` і `audit_triggers.py`. Установка без лінтів не
   вважається завершеною — бандл міг привезти споживача без власника.
5. **Прибрати бекапи** лише після того, як Mark підтвердив, що нове працює.
   Самому не видаляти.

## Inter-Skill API

### Owns
Нічого. Читає архів, пише теки в чужий корінь скілів. Власник кореня —
`skills-sync` (git-сторона) і сам акаунт.

### Public Interface (Inter-Skill API)
- `skill-creator-set-unpack.unpack(bundle, root?, force?, dry_run?) → [status_lines]` —
  верифікація → план → встановлення. Відмовляє при розбіжності sha256.
- `skill-creator-set-unpack.inspect(bundle) → manifest_dict` — прочитати маніфест
  без запису на диск (еквівалент `--dry-run` без кореня).
- `skill-creator-set-unpack.emit(bundle, out_dir) → [paths]` — розібрати бандл на
  окремі `.skill` без установки, байт-у-байт. Для середовищ без записуваного
  кореня скілів; перевірка sha256 діє так само і так само блокує при розбіжності.

### Internal (do not call from outside)
- _розбір `skills/*.skill`, визначення кореневої теки всередині `.skill`,_
  _іменування бекапів, тимчасовий staging перед копіюванням._

## Gotchas

- **Розбіжність sha256 — це стоп, не попередження.** Скрипт виходить із кодом 2
  і не пише нічого. Означає, що архів змінили після збірки; перезібрати з джерела,
  а не примушувати.
- **Голий `.skill` не має маніфесту.** Ставиться, але без перевірки хешу і без
  порядку — для одного скіла це нормально, для пачки ні.
- **Порядок із маніфесту, не алфавітний.** Власники інтерфейсів ідуть першими;
  переставляти вручну — значить ставити споживача перед контрактом.
- **`.bak-*` теки лишаються в корені скілів.** Якщо корінь під git — вони
  потраплять у `git status`; додати в `.gitignore` або прибрати перед комітом,
  інакше `skills-sync` понесе їх у бекап-репу.
- **Скрипт не перезавантажує скіли в живій сесії.** Після встановлення потрібен
  новий контекст, щоб description оновлених скілів потрапили в тригерний простір.
