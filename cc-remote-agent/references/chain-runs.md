# Ланцюги ранів

Читати, коли ранів більше одного в тій самій робочій копії. Базове правило — крок 4b у `SKILL.md`.

## Коли ланцюг, а коли паралельно

| Ситуація | Як пускати |
|---|---|
| Рани в різних репо, різні цілі деплою | паралельно, кожен своїм `flock` по slug |
| Рани в одній робочій копії | **ланцюг** — `flock` тримає slug, не репо |
| Рани в різних репо, але одна веб-тека деплою | **ланцюг** або різні цілі; інакше затруть одне одного |
| Рани, де наступний спирається на результат попереднього | **ланцюг**, і це єдиний коректний варіант |

## plan-файл

Рядок на ран:

```
slug|style|/abs/path/task.md
```

- `slug` — латиниця й дефіси, ≤ 24 символи; стає префіксом `run_id`
- `style` — `caveman` | `ponytail` | `none`
- `none` означає запуск без `--settings` взагалі — це контрольна група для заміру ароматів, а не «стиль за замовчуванням»
- рядок, що починається з `#`, ігнорується

`{RUN_ID}` усередині `task.md` підставляється реальним id на спавні — тому один і той самий `task.md` можна переганяти повторно.

## Коди виходу драйвера

| Код | Значення | Що робити |
|---|---|---|
| 0 | усі рани дали `RESULT: ok` | верифікувати транспортом (крок 6), далі деплой |
| 2 | ран не дав `ok` | гілка лишена як є; читати `out.log` того рану, не всього ланцюга |
| 3 | `session limit` | не провал; добити решту плану окремим ланцюгом пізніше |
| 1 | не вдалось створити гілку | брудна робоча копія або зайнята назва гілки |

## Черга за вже запущеним ланцюгом

Драйвер не тримає замок після старту (спавн ішов у фон), тому чергу не можна побудувати на `flock`. Воркер чекає процес і **перевіряє, що попередній ланцюг дійшов до кінця**:

```sh
#!/bin/sh
set -u
RUNS=${CC_RUNS:-$HOME/cc-runs}
CWD=${1:?cwd}; PLAN=${2:?plan}; TAG=${3:-chain2}
while pgrep -f "cc-chain.sh $CWD" > /dev/null; do sleep 30; done
prev=$(ls -t "$RUNS"/*-*.log | head -1)
grep -q "ланцюг пройшов повністю" "$prev" || { echo "попередній не дійшов ($prev) — стоп"; exit 2; }
sh "$RUNS/cc-chain.sh" "$CWD" "$PLAN" "$TAG"
```

Без перевірки попереднього логу черга поставить другий ланцюг поверх зламаного стану — рівно те, від чого захищає інваріант «стоп на першому не-ok».

## Деплой у кінці ланцюга

Автодеплой чіпляти **після** драйвера й **тільки** на нульовий код виходу. Три правила, які коштували найдорожче:

1. **Ціль деплою ранів ≠ тека, яку зараз перевіряє людина.** Поки Марк дивиться staging — рани деплоять у dbg. Інакше ран стирає предмет перевірки.
2. **`sw.js` на перевірочних теках — kill-switch, не збірковий.** Збірковий service worker закешує білд, і людина дивитиметься на привида замість свіжого коду.
3. **Бекап попереднього `index.html` з таймстемпом** перед перезаписом, поруч у тій самій теці.

## Аромати в ланцюзі

Порівнянна пара — це два рани **одного класу задачі** з різними стилями. Ланцюг дає для цього найкращі умови (та сама кодова база, той самий день) і водночас вносить систематичне спотворення: ран, що йде другим, має перед очима результат першого. Фіксуй порядок разом зі стилем, інакше приріст швидкості припишеться стилю замість ефекту порядку.

Рани, що отримали додаткову роботу вже після написання промпта, з пари вибувають — вони більше не одного класу.
