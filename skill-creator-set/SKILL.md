# skill-creator-set

Кілька скілів, одна причина, один архів.

Inherits from: `skill-creator-pack` (behavioural — кожен скіл пакується ним)
Overrides: додає маніфест, порядок встановлення, перевірку когерентності сету
Reuses verbatim: нормалізація frontmatter, валідація, формат `.skill`

**Крок 0:** прочитати скіл `skill-creator-framework` (його `SKILL.md`), далі
read `skill-creator-pack` — його `SKILL.md` за шляхом
скіл `skill-creator-pack` (його `SKILL.md`).

---

## Коли це, а не `-pack` ×N

Чотири окремі `.skill` не кажуть отримувачу, що їх треба ставити разом і в якому
порядку. Якщо власник публічного інтерфейсу поїхав без споживачів — вони
викликають операції, яких ще нема; якщо споживачі поїхали без власника —
навпаки. Маніфест і є тим, чого бракує: він фіксує **причину**, а не лише вміст.

Ознака, що потрібен сет: серед відредагованих скілів є хоч одна пара, зв'язана
`Depends on:` або `Inherits from:`. Немає такої пари — це просто кілька скілів,
пакуй `-pack` окремо і не вигадуй бандл.

## Процедура

1. **Визначити сет.** Прогнати `lint_dependencies.py` зі
   `skill-creator-framework` по відредагованих скілах. Кожен споживач, якого він
   репортить для зміненого власника, **мусить** бути в сеті — інакше бандл
   везе поламаний контракт.
2. **Спакувати кожен** через `skill-creator-pack.pack()`.
3. **Порядок.** Власники інтерфейсів і батьки — перші, споживачі й нащадки —
   за ними. Якщо порядок неочевидний, він виводиться з `Depends on:`.
4. **Зібрати.**
   ```
   python scripts/build_bundle.py <out>.skillset \
     --reason "<що саме змінилось у контракті>" \
     --order <owner>,<consumer>,<consumer> \
     dist/a.skill dist/b.skill ...
   ```
   `--reason` обов'язковий: бандл без заявленої причини — це тека.
5. **Верифікація.** `unzip -p <bundle> MANIFEST.md` — прочитати очима. Версії
   `—` у власника стейту означають, що `metadata.version` не проставлено;
   за §7 фреймворку це дефект, повідомити Марку.
6. **Віддача.** `present_files` на `.skillset`.

## Inter-Skill API

### Owns
Нічого. Stateless — читає `.skill`-файли, пише один архів.

### Public Interface (Inter-Skill API)
- `skill-creator-set.bundle(skill_files, reason, order?) → path_to_skillset` —
  маніфест + zip. Помилка, якщо `reason` порожній.
- `skill-creator-set.inspect(skillset) → manifest_dict` — читає `MANIFEST.json`
  з архіву без розпакування.

### Internal (do not call from outside)
- _формат `skillset/1`, розкладка `skills/` всередині архіву, парсинг_
  _`metadata.version` з вкладеного SKILL.md, обчислення sha256._

## Gotchas

- **Бандл не встановлює.** На тому боці — розпакувати кожен `.skill` у корінь
  скілів у порядку з маніфесту, потім прогнати лінти. Автоінсталера тут нема
  і не буде: підкладати файли в живий акаунт наосліп — гірше, ніж зайвий крок.
- **`.skillset` — не формат платформи.** Це локальна конвенція цієї колекції.
  Розпакувати вручну може будь-хто, але жоден офіційний інсталер його не знає.
- **sha256 у маніфесті — від `.skill`-файлів, не від вмісту скілів.** Перепакування
  того самого скіла дає інший хеш через таймстемпи в zip. Хеш ловить підміну
  файлу дорогою, не порівнює версії.
- **Сет ≠ синк.** Бандл — це артефакт для перенесення руками. Регулярне
  вирівнювання живих скілів з `skills-backup` робить `skills-sync` через git,
  і воно не потребує пакування взагалі.
